# TypeScript class：字段、继承与多态

NekoC 支持可静态确定类型的 class 声明、实例字段、构造函数、参数属性、
`new`、实例方法和 `this`，以及第 2 步的继承、`super`、abstract、`instanceof`、
多态方法/访问器和 static 字段、方法。class 实例沿用
[普通对象的全局列表堆和数字句柄](ts-share-objects.md)，生成作品不依赖
`_object_*` 私有积木。

```ts
class Counter {
  value = 0;

  constructor(public step: number) {}

  add(amount: number): number {
    this.value += amount;
    return this.value;
  }

  advance(): number {
    return this.add(this.step);
  }
}

const counter = new Counter(3);
const alias = counter;
console.log(counter.advance()); // 3
alias.add(2);
console.log(counter.value);     // 5
console.log(alias === counter); // true
```

## 数据布局

class 字段加入全程序共享的静态属性槽位表。每个实例在隐藏全局列表
`__nekocObjectHeap` 中占用相同宽度 `W` 的连续单元，实例值是首个单元的
1 基数字句柄。字段名对应固定槽位 `slot`，官方列表积木的访问位置是
`handle + slot`。空类也保留至少一个单元，使两次 `new` 拥有不同身份。

方法不占用实例字段槽位，实例不保存 JavaScript 函数或原型。实例别名、
数组元素、对象字段、函数参数和返回值只传递同一个句柄；引用相等比较
直接比较句柄。实例字段可以保存另一个实例、普通对象或数组。

分配过程使用官方列表、自制积木和 `warp`。`warp` 保证一轮分配追加的
`W` 个单元不会被其他协作脚本的分配穿插。内部预留槽位的值不能作为
JavaScript 的 `undefined` 被用户读取。

## 创建实例与初始化顺序

`new C(args)` 降低为返回实例句柄的工厂过程，顺序为：

1. 按源码顺序对显式构造函数实参求值一次。
2. 分配实例的完整字段布局。
3. 按字段声明顺序执行字段初始化表达式；它们可以通过 `this` 读取已初始化
   字段、写入字段或调用实例方法。初始化表达式保留类声明位置的词法作用域。
4. 进入构造函数，应用省略参数的默认表达式，赋值参数属性，然后运行构造函数体。
5. 返回原实例句柄。构造函数中的独立 `return;` 提前结束构造函数体，仍由
   `new` 返回该实例。

字段初始化早于构造函数体，也早于构造函数参数属性的赋值。不要在字段
初始化表达式中读取尚未初始化的参数属性；在构造函数体中完成依赖该参数
属性的计算。`constructor(public x: number)`、TypeScript 的 `private` /
`protected` / `readonly` 参数属性均可声明实例字段；`#x` 私有名字不支持。

可选字段 `x?: T` 和类型含 `null` / `undefined` 的无初始值字段在分配时写入
undefined 哨兵，读出 `undefined`；`next: Node | null = null` 这类可空字段照常
初始化（见 [null / undefined 与可选链](ts-nullable.md)）。其他无初始值的字段
必须在所有构造函数路径结束前赋值。前向字段读取、未初始化字段读取及字段初始化完成前让 `this`
逃逸会产生带源码位置的错误。请显式初始化字段，或使用标量有效性标记。
编译器不会将堆中保留的 `0` 解释成 JavaScript 的缺失字段值。
构造函数默认参数可能被显式实参跳过，因此其中的字段赋值不能作为必定
初始化的依据；前面的字段初始化器写入后面的无初始值字段，也不能替代
后者的显式初始化。

## 方法调用与递归

每个实例方法降低为一个普通函数，再由现有函数编译路径生成自制积木。
第一个隐藏的业务参数是实例 `this` 句柄；`this.x` 与普通对象属性共用
列表读取、替换和复合赋值路径。

调用 `receiver().method(argument())` 先对接收者求值一次，再按顺序对实参
求值一次，最后将接收者句柄作为首个参数传入方法过程。接收者别名在实参
求值过程中被修改，不会更换这次调用已经选定的实例。

方法可以返回标量或实例，可以通过 `this.other()` 互相调用，也可以直接
或相互递归。每次过程调用通过隐藏参数 `__nekocFrame` 获得独立帧列表，
保存局部变量和需要跨递归调用保留的临时值；不同实例之间的递归调用保持
各自的 `this`。属性复合赋值在右侧求值前保存接收者和旧字段值。
无返回值的方法只能作为独立语句调用；有返回值的方法必须在每条路径显式
返回具体值，不能读取隐式的 `undefined` 结果；返回类型含 `undefined` 时，
`return;` 和 `return undefined;` 都返回 undefined 哨兵。当前返回路径证明支持顺序
语句及完整的 `if` / `else` 分支；复杂控制流可在末尾增加显式返回。

带参数的自制积木继续使用官方参数 id：定义中的
`procedures_2_stable_parameter` id 与过程 `params` 的 id 相同，引用积木的
mutation 带对应 `id`。返回值积木带 `items="1"` mutation 和数字阴影块。

## 支持范围与静态类型

- 顶层具名 class 声明、普通字段、字段初始值、一个构造函数及参数属性。
- `new C(...)`、实例字段读写、算术和文本复合赋值，以及作为语句使用的
  `this.x++`、`++this.x`、`this.x--`、`--this.x`。
- 实例方法返回值、方法互调和递归，包括局部变量及跨实例递归调用。
- 实例在数组、对象字段、普通函数参数和返回值中的传递，别名和引用比较。
- TypeScript checker 静态确定接收者 class 或基类后的方法调用；不同 class
  可以声明同名方法，继承树内按需要虚分派。

接收者必须保持类身份或其祖先类型。`any`、`unknown`、不相关类联合以及
不相关结构类型赋值不能用来选择方法；请使用明确的类或共同基类标注，
并用 instanceof 收窄后访问子类成员。普通对象已有的动态 key、
容器类型擦除、对象 coercion、JSON 等限制仍适用。

## 继承树、类编号与布局

每棵继承树按声明顺序先序遍历。类 C 对应 `[pre(C), post(C)]` 区间，
实例的隐藏字段存储最终实际类编号。判断实例是 C 或其子类只需读取编号
并比较区间。子类包含所有祖先字段，同名字段沿用全程序共享的同一个槽位；
子类初始化器按 JS 时序覆盖该槽位。内部使用每棵树的完整引用字段形状，
保证实例经父类参数或数组传递时保留嵌套引用。
同一继承树中同名字段必须具有相同类型，包括兄弟子类；不同类型请使用
不同字段名，避免共享类型形状改变算术或文本运算的含义。子类同名字段的
初始化表达式仍可读取父类构造留下的值，再覆盖该槽位。

只有第 1 步语法的程序仍走原路径，编译报告保持一致，不增加类编号读取
或分派积木。继承程序中没有后代重写的方法同样保持直接调用。

## 派生类构造顺序

`new` 分配同一个完整句柄并写入实际类编号，再执行构造链。基类字段和
构造体先完成；派生类在 `super()` 返回后才执行自身字段初始化、参数属性
赋值及剩余构造语句。派生类默认参数和 `super()` 前普通语句先执行。
没有构造函数的子类透传参数给父类，再初始化自己的字段。

每条派生构造路径必须恰好调用一次 `super()`，此前不能使用或捕获 this，
也不能访问 super 成员。支持顺序代码和完整 if/else；循环、switch、try
内的 super 无法证明恰好一次，会明确拒绝。super 必须是独立语句。

构造期间可能到达后代重写的 `this.m()`、getter 或 setter 一律保守拒绝，
即使该重写恰好只返回常量；把调用移到 new 之后，或调用没有被重写的
初始化方法。存在子类时，构造期间也拒绝把完整 this 传出或存成别名，
避免外部函数间接调到尚未初始化子类字段的实现。

## 多态、abstract 与 instanceof

接收者静态类型可以是父类，包括父类数组、对象字段、参数与返回值。
子类可向祖先类型传递，结构相同但不相关的类不能替换；未经 instanceof
收窄的父类到子类断言也不能伪造子类。any、unknown 和不相关联合接收者
仍拒绝；同一继承树的联合按共同的具名基类分派。

有后代重写时按静态接收者类和方法生成分派过程，读取实际类编号，用
if 区间分支选实现。相邻编号使用同一实现时合并，最后一项直接返回。
接收者先求值一次，实参依次各求值一次；省略参数留给实际实现计算默认值。
重写实现可减少参数数目；所有调用实参仍先求值，再只转发目标实现需要的
参数，保留未使用实参的副作用。括号包裹的方法调用保持同一个实例接收者。
`super.m()` 直接调用父类或祖先实现；该实现内部的 this 调用仍虚分派。

abstract 类不能 new，abstract 方法/访问器不生成具体实现；非 abstract
子类必须实现全部抽象成员，TS 的继承兼容与抽象实现诊断会传出。
`x instanceof C` 要求右侧是静态已知的类标识符、左侧是类或父类引用，
降低成编号区间判断；TS checker 的原始类型收窄决定分支内可调用的成员。

## getter / setter

属性读写降低为 get/set 方法调用，重写时使用相同的虚分派规则。
`receiver().p += rhs()` 先保存接收者、调用 getter，再执行 RHS，最后调用
setter；接收者和旧值保存在独立调用状态，递归不会覆盖。独立 ++/-- 同样
先 get 后 set。只有 getter 时写入、只有 setter 时读取都会报错。子类
只声明半个访问器按 JS 规则遮蔽父类整对访问器，不自动补齐另一半。
支持 super.p 和 super.p = value 直接调用祖先访问器。

访问器赋值/更新限独立语句；逻辑复合赋值 &&=/||=/??= 使用显式 if。
字段、方法与访问器之间的继承覆盖暂不支持，使用不同成员名。

## static

static 字段降低成隐藏全局变量，static 方法是没有 this 首参的普通函数。
字段初始化保留 class 声明的源码位置，按成员声明顺序执行，与前后顶层
语句保持时序。使用 DeclaringClass.field / DeclaringClass.method()。
字段必须有显式初始值；初始化时沿调用路径检查未完成 static 字段的读取，
避免把 undefined 变成 VM 的默认 0。
检查包括方法、访问器、构造函数、实际执行的默认参数以及同步回调中的
间接读取；显式传入实参时跳过对应默认表达式。通过函数间接 new 也必须
发生在目标 class 声明求值之后。初始化期间不能证明安全的回调会保守拒绝，
请把依赖后续 static 字段的调用移到 class 声明之后。

明确拒绝 static 成员里的 this、static 继承访问（Sub.inheritedStatic）、
static getter/setter 及 static 块。改用显式声明类名、普通静态方法和
初始化函数。

## 拒绝范围

以下写法会给出带源码位置的错误，并说明限制或提供替代写法：

- mixin、继承内置 Array/Error/Map 等类型：extends 后使用静态已知的具名 class。
- static this、继承访问、访问器及初始化块：使用声明类名、普通静态方法。
- `#` 私有字段、索引签名、动态成员名：改用具名字段和显式方法。
- 方法值、方法回调、`.bind`、`.call`、`.apply`：直接调用 `obj.method(args)`，或者声明
  接收实例参数的普通函数。
- 可能跨让出边界存活的 `this` 或其别名捕获：改用直接方法调用和显式实例参数。
  `super` 成员访问同样隐式捕获 this；检查包含虚方法重写、访问器和默认参数
  中的间接让出。普通嵌套函数自身的动态 `this` 绑定也不支持。
- class 表达式、嵌套运行时 class、装饰器：使用顶层具名 class 和显式初始化。
- 运行时添加实例属性：在 class 中声明并初始化所有字段。
- 方法重载、泛型 class / 方法、async / generator 方法、函数值字段：使用具体
  字段类型和普通实例方法。
- 构造函数返回替换值、缺少必要实参、额外或 spread 构造实参：保持一个明确
  的构造签名，显式传入实参或声明具体默认值。
- 需要取得属性 `++` / `--` 表达式值的写法：拆成独立更新语句和显式读取。

普通函数的默认参数限制同样适用于方法；方法默认参数中读取 `this` 暂不支持，
请在调用处显式传入字段值，或在方法体内读取。无法按现有函数规则确定其他
默认值时，请在调用处显式传入实参。其他尚未实现的 JavaScript 语义也不会通过宿主对象
或私有对象积木兜底。

当前支持同一源文件内的类及继承，跨模块 class 继承和动态类值不在此轮
范围内。隐藏帮助函数与编号不是用户 API。

- `tests/ts-classes.test.mjs`：字段、构造、参数属性、方法、递归、引用身份、求值
  顺序、拒绝诊断与官方积木格式检查，并沿用 `tests/ts-runtime.mjs` 的 Node / VM
  差分框架。
- `tests/ts-classes-review.test.mjs`：作用域、初始化前读取、结构类型身份及闭包
  捕获等组合回归用例。
- `tests/ts-classes-boundaries.test.mjs`：既有数组语法、提前返回、默认参数、
  class 声明时序和间接让出边界等诊断回归。
- `tests/fixtures/ts-classes.ts`：同一份源代码在 Node 和 `nekoc run` 中输出
  33 条标量日志，不输出内部句柄。
- `tests/ts_classes.rs`：在解释器和 JIT 两种执行模式下核对该 fixture 的完整日志。
- `tests/ts-classes-inherit.test.mjs`：继承、构造链、虚分派、abstract、
  instanceof、访问器、static、优化及拒绝诊断。
- `tests/fixtures/ts-classes-inherit.ts`：23 条标量日志，在 Node、解释器和
  JIT 中逐条一致。既有 289 条 JS 差分用例继续运行。
- `tests/ts-classes-inherit-safety.test.mjs`：默认参数、class 声明时序、
  静态初始化间接读取、super/虚调用/访问器的让出捕获，以及未使用类回归。

生成的 class 示例还须执行 `node tools/editor-compat.mjs <作品.bcmkn>`，只有
`ok: true` 视为通过编辑器兼容检查；这不替代运行语义及完整分享发布链路验证。
