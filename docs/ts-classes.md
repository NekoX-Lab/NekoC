# TypeScript class：第 1 步

NekoC 支持可静态确定类型的 class 声明、实例字段、构造函数、参数属性、
`new`、实例方法和 `this`。这一阶段没有继承和原型查找；class 实例沿用
[普通对象的全局列表堆和数字句柄](ts-share-objects.md)，生成作品不依赖
`_object_*` 私有积木。

```ts
class Counter {
  value = 0;

  constructor(public step: number) {}

  add(amount: number): number {
    this.value += amount;
    return this.value;
  }

  advance(): number {
    return this.add(this.step);
  }
}

const counter = new Counter(3);
const alias = counter;
console.log(counter.advance()); // 3
alias.add(2);
console.log(counter.value);     // 5
console.log(alias === counter); // true
```

## 数据布局

class 字段加入全程序共享的静态属性槽位表。每个实例在隐藏全局列表
`__nekocObjectHeap` 中占用相同宽度 `W` 的连续单元，实例值是首个单元的
1 基数字句柄。字段名对应固定槽位 `slot`，官方列表积木的访问位置是
`handle + slot`。空类也保留至少一个单元，使两次 `new` 拥有不同身份。

方法不占用实例字段槽位，实例不保存 JavaScript 函数或原型。实例别名、
数组元素、对象字段、函数参数和返回值只传递同一个句柄；引用相等比较
直接比较句柄。实例字段可以保存另一个实例、普通对象或数组。

分配过程使用官方列表、自制积木和 `warp`。`warp` 保证一轮分配追加的
`W` 个单元不会被其他协作脚本的分配穿插。内部预留槽位的值不能作为
JavaScript 的 `undefined` 被用户读取。

## 创建实例与初始化顺序

`new C(args)` 降低为返回实例句柄的工厂过程，顺序为：

1. 按源码顺序对显式构造函数实参求值一次。
2. 分配实例的完整字段布局。
3. 按字段声明顺序执行字段初始化表达式；它们可以通过 `this` 读取已初始化
   字段、写入字段或调用实例方法。初始化表达式保留类声明位置的词法作用域。
4. 进入构造函数，应用省略参数的默认表达式，赋值参数属性，然后运行构造函数体。
5. 返回原实例句柄。构造函数中的独立 `return;` 提前结束构造函数体，仍由
   `new` 返回该实例。

字段初始化早于构造函数体，也早于构造函数参数属性的赋值。不要在字段
初始化表达式中读取尚未初始化的参数属性；在构造函数体中完成依赖该参数
属性的计算。`constructor(public x: number)`、TypeScript 的 `private` /
`protected` / `readonly` 参数属性均可声明实例字段；`#x` 私有名字不支持。

运行时尚无 `undefined` 字段存储。无初始值的字段必须在所有构造函数路径
结束前赋值。前向字段读取、未初始化字段读取及字段初始化完成前让 `this`
逃逸会产生带源码位置的错误。请显式初始化字段，或使用标量有效性标记。
编译器不会将堆中保留的 `0` 解释成 JavaScript 的缺失字段值。
构造函数默认参数可能被显式实参跳过，因此其中的字段赋值不能作为必定
初始化的依据；前面的字段初始化器写入后面的无初始值字段，也不能替代
后者的显式初始化。

## 方法调用与递归

每个实例方法降低为一个普通函数，再由现有函数编译路径生成自制积木。
第一个隐藏的业务参数是实例 `this` 句柄；`this.x` 与普通对象属性共用
列表读取、替换和复合赋值路径。

调用 `receiver().method(argument())` 先对接收者求值一次，再按顺序对实参
求值一次，最后将接收者句柄作为首个参数传入方法过程。接收者别名在实参
求值过程中被修改，不会更换这次调用已经选定的实例。

方法可以返回标量或实例，可以通过 `this.other()` 互相调用，也可以直接
或相互递归。每次过程调用通过隐藏参数 `__nekocFrame` 获得独立帧列表，
保存局部变量和需要跨递归调用保留的临时值；不同实例之间的递归调用保持
各自的 `this`。属性复合赋值在右侧求值前保存接收者和旧字段值。
无返回值的方法只能作为独立语句调用；有返回值的方法必须在每条路径显式
返回具体值，不能读取隐式的 `undefined` 结果。当前返回路径证明支持顺序
语句及完整的 `if` / `else` 分支；复杂控制流可在末尾增加显式返回。

带参数的自制积木继续使用官方参数 id：定义中的
`procedures_2_stable_parameter` id 与过程 `params` 的 id 相同，引用积木的
mutation 带对应 `id`。返回值积木带 `items="1"` mutation 和数字阴影块。

## 支持范围与静态类型

- 顶层具名 class 声明、普通字段、字段初始值、一个构造函数及参数属性。
- `new C(...)`、实例字段读写、算术和文本复合赋值，以及作为语句使用的
  `this.x++`、`++this.x`、`this.x--`、`--this.x`。
- 实例方法返回值、方法互调和递归，包括局部变量及跨实例递归调用。
- 实例在数组、对象字段、普通函数参数和返回值中的传递，别名和引用比较。
- TypeScript checker 静态确定接收者具体 class 后的直接方法调用；不同 class
  可以声明同名方法。

接收者必须保持同一个具体 class 类型。`any`、`unknown`、联合类型以及
改变 class 身份的结构类型赋值或断言都不能用来选择方法；请保持具体类的
类型标注，并在调用前用显式程序分支选择具体实例。普通对象已有的动态 key、
容器类型擦除、对象 coercion、JSON 等限制仍适用。

## 第 1 步拒绝范围

以下写法会给出带源码位置的错误，并说明限制或提供替代写法：

- `extends`、`super`、`abstract`、`instanceof`：留给第 2 步。当前可将其他实例
  保存在字段中，通过显式方法组合行为，用已声明的标量字段区分种类。
- `static` 字段、方法和初始化块：改用顶层变量或普通函数。
- `#` 私有字段、getter/setter、索引签名、动态成员名：改用具名字段和显式方法。
- 方法值、方法回调、`.bind`、`.call`：直接调用 `obj.method(args)`，或者声明
  接收实例参数的普通函数。
- 可能跨让出边界存活的 `this` 或其别名捕获：改用直接方法调用和显式实例参数。
  普通嵌套函数自身的动态 `this` 绑定也不支持。
- class 表达式、嵌套运行时 class、装饰器：使用顶层具名 class 和显式初始化。
- 运行时添加实例属性：在 class 中声明并初始化所有字段。
- 方法重载、泛型 class / 方法、async / generator 方法、函数值字段：使用具体
  字段类型和普通实例方法。
- 构造函数返回替换值、缺少必要实参、额外或 spread 构造实参：保持一个明确
  的构造签名，显式传入实参或声明具体默认值。
- 需要取得属性 `++` / `--` 表达式值的写法：拆成独立更新语句和显式读取。

普通函数的默认参数限制同样适用于方法；方法默认参数中读取 `this` 暂不支持，
请在调用处显式传入字段值，或在方法体内读取。无法按现有函数规则确定其他
默认值时，请在调用处显式传入实参。其他尚未实现的 JavaScript 语义也不会通过宿主对象
或私有对象积木兜底。

## 验证入口

- `tests/ts-classes.test.mjs`：字段、构造、参数属性、方法、递归、引用身份、求值
  顺序、拒绝诊断与官方积木格式检查，并沿用 `tests/ts-runtime.mjs` 的 Node / VM
  差分框架。
- `tests/ts-classes-review.test.mjs`：作用域、初始化前读取、结构类型身份及闭包
  捕获等组合回归用例。
- `tests/ts-classes-boundaries.test.mjs`：既有数组语法、提前返回、默认参数、
  class 声明时序和间接让出边界等诊断回归。
- `tests/fixtures/ts-classes.ts`：同一份源代码在 Node 和 `nekoc run` 中输出
  33 条标量日志，不输出内部句柄。
- `tests/ts_classes.rs`：在解释器和 JIT 两种执行模式下核对该 fixture 的完整日志。

生成的 class 示例还须执行 `node tools/editor-compat.mjs <作品.bcmkn>`，只有
`ok: true` 视为通过编辑器兼容检查；这不替代运行语义及完整分享发布链路验证。
