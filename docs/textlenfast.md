# 不可变文本的 UTF-16 长度缓存

`Text` 叶子在构造时计算 UTF-16 code-unit 数，拼接节点用 checked addition
保存两个子节点长度之和；空串复用、共享 DAG、已平坦化前缀转为叶子的路径均保留此缓存。
`Text::len()` 仍是 **UTF-8 字节数**，新入口 `Text::utf16_len()` 才是 UTF-16 单元数，
不是 Unicode 码点数或可见字形数。例如 `😀` 为 2，`é` 为 2。

`Cell::text_length()` 对不可变文本直接读缓存，不分配、不遍历、不创建平坦缓存。
其他 Cell（包括可变/循环列表、数字、布尔、null、undefined、对象等）仍调用原来的
`text().encode_utf16().count()`，因此不改变既有强制转换、负零或非有限数格式。
Engine 的解释器和 native `h_node` helper 共用这个入口；输入仍仅求值一次。
没有修改字符串截取、索引、数字解析、KN/K4 加法或 rope 平衡策略。

长度溢出与原字节长度一样显式 panic，release 也不会静默环绕。
合法 Rust UTF-8 文本的 UTF-16 数不大于字节数，因此有效节点的 UTF-16 累加不会先于
字节长度溢出。该缓存每节点增加一个 `usize`；短文本或纯拼接未必受益。
Rust `str` 不能表示孤立代理项；本改动不扩展此前的表示边界，不宣称完整 JS 字符串兼容。
null 的既有文本转换为空串（不是 JS `String(null)`）；本任务保留这个运行时约定。
此改动只影响本地 Engine 的实现，不改 TS 降低结果或生成任何新积木类型。
没有新增或修改落盘 `.bcmkn` 夹具，不把本地差分当作官方编辑器/分享播放器实测。

## 确定性回归

- `tests/fixtures/textlenfast.json` 的预期值由 Node `.length` 检查，并供 Rust 共同读取。
- `tests/textlenfast.rs` 覆盖所有 Cell tag、可变/循环列表，KN/K4 左右增长文本，
  有副作用的 reporter 单次执行、输出日志、逐帧 typed 状态和真实热 native region。
- `tests/textlenfast/internal.rs` 检查叶子分割、flat 前缀脱离、深左右树、共享 DAG、
  溢出，确认反复读取长度没有使任何内部节点平坦化。
- `tests/textlenfast_bench.rs` 的普通测试用线程局部分配计数验证零分配长度读取；
  忽略测试仅供本地 release 计时，CI 没有墙钟阈值。

## 本地 release AB/BA

先把 `tests/textlenfast_bench.rs` 的相同基准函数放在未优化运行时上构建
（不包含依赖新 API 的 `allocation_tests` 模块），再在优化运行时构建；
分别复制 Cargo JSON artifact 中的测试 executable 到当前 worktree 的 `dist/textlenfast/`。
不要混用其他提交的现成可执行文件。所有 cargo 调用遵守任务机器的全局信号量，例如：

```bash
bash E:/nekoc-wt/_cargo.sh test --release --test textlenfast_bench --no-run --message-format=json
node tools/bench/textlenfast-ab.mjs dist/textlenfast/before.exe dist/textlenfast/after.exe dist/textlenfast/results.json
```

runner 对五个用例分别运行解释器/JIT，每项六对独立进程，AB/BA 交替，
虚拟时钟，每帧一个 2000 次循环的 batch，共 16 帧（前 6 帧含热编译、后 10 帧稳定采样）。
包含固定长串反复读、边增长边读、纯数值、原 KN 字符串控制项
（每 batch 重置后拼接 2000 次 `abcdefgh`）、短串拼接控制项。
记录完整终态并逐对断言相等、Engine 构建时间/分配、逐帧时间/分配。
同时按 Node 的字符串拼接和 `.length` 规则校验固定/增长终态，避免两边共同算错。
前六帧包含 JIT 编译成本，不当作纯执行时间；测量不启用 JIT profile/timing。
分配量为当前线程向 System 请求的次数/字节（realloc 记新请求大小），不是峰值或存活内存；
分配计数本身会扰动计时。终态快照在计时窗口外，基准不落盘生成 `.bcmkn`。
结果只表示该机受控用例，不沿用历史字符串 benchmark 的倍数，也不等于官方播放器计时。
