# TS 展开与剩余边界（r4-tsspread）

本轮选择明确编译报错，不实现不完整的展开降级。以下运行时语法在原始
AST 上、任何默认参数/函数/类/集合降级之前校验；未调用函数、死分支、
回调、默认表达式、类继承表达式和传递导入中也不会静默忽略。`build` 不生成作品，`check --no-types`
同样返回兼容性错误，通常定位原文件中的 `...`。为保持既有诊断兼容，
String.replace/replaceAll 调用展开定位整个调用，数组解构赋值的展开 RHS
定位整个 RHS 数组。KN 和 K4 共用 `ts/js-support.mjs` 的原始 AST 检查，
不再另设重复的 spread 校验器。

| 写法 | 结果 | 可用替代 |
| --- | --- | --- |
| `[...a, 4]`、`[..."ab"]` | Array spread 错误 | 对数组使用 `a.slice().concat([4])`；字符串/迭代器另写显式遍历 |
| `{ ...source, x: 2 }` | Object spread 错误 | 先保存 source，再显式复制已知数据属性到新对象 |
| `function f(...args: number[])` | Rest parameters 错误 | 改成普通数组参数 `f(args: number[])`，调用方显式传数组 |
| `f(...a)`、`new C(...a)`、`Math.max(...a)` | Spread arguments 错误 | 显式传入各个参数；动态参数个数改写为数组处理函数 |
| `f(...[])`、`f(...[undefined, 2])` | Spread arguments 错误 | 显式调用 `f()`、`f(undefined, 2)` |
| `function f(a = 7, ...tail)` | Rest parameters 错误 | 改成显式数组参数，保留原有默认参数边界 |
| `const [head, ...tail] = array` | 保留已有支持 | 新数组浅拷贝剩余元素，元素引用保持共享 |
| `[...tail] = array`、`const { x, ...rest } = source` | 明确错误 | 显式语句、`slice()` 或已知属性复制 |

纯类型中的函数 rest 签名和 tuple rest 不属于运行时展开，不被此校验器
拒绝。注释、字符串里的 `...` 也不受影响。其它既有 TS 子集限制仍适用。

## 为什么不能直接去掉省略号

数组展开需要按迭代顺序拷贝元素并新建数组，而不是把整个数组作为一个
元素。调用展开会改变实参数量；空展开、展开中的 undefined 会影响默认
参数触发。还必须保留每个操作数的单次求值、从左到右顺序、浅拷贝身份和
后续副作用。对象展开也必须按位置覆盖并保留浅引用。只把 `...a` 编译成
`a` 会静默生成错误语义。

本次回归覆盖明确拒绝、源位置、传递导入、KN/K4、CLI、npm/browser 前端，
以及未改变的数组 binding rest、普通默认参数和显式 slice/concat 替代。
支持路径用 Node 执行同源 TS 转译结果作为 JS 语义基准。

## 证据与未验证

- 这是编译器语法能力限制，不是“官方积木不能表达展开”的断言。
- 没有新增运行时积木，也未移植 HateNeko 代码。
- Node 对比只能证明本项目 VM 的 JS 回归结果，不能代替官方播放器行为
  证据；官方播放器逐项运行语义本轮未验证。
- 官方编辑器结构兼容检查结果及具体命令记录在本次 `OC-REPORT.md`。

## 后续
