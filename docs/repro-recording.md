# Web 播放器复现录制包

## 使用

1. 在独立 Web 播放器 `/play` 导入作品，点击 **录制复现（从头开始）**。这会重启作品，固定种子 `1`、每帧 `1/60` 秒、UTC 2000-01-01 起点，关闭合并更新与真实时间预算。录制与普通游玩是不同的运行模式。
2. 在舞台操作键盘、鼠标或触屏。可以暂停/继续；切到后台自动暂停。
3. 点击 **停止录制并导出 JSON**，保存 `neko-repro.json`。只保存已收到后端确认的帧；断线时仍可导出最后确认的片段，诊断中标记 `interrupted`。最多 36,000 帧，或约 16 MiB 紧凑输入；到限暂停，等待导出。
4. 另行提供同一作品文件，用相同版本的 NekoC 执行：

```sh
nekoc run original.bcmkn --input-script neko-repro.json --out replay.json
# Kitten 4 .bcm 同样支持
nekoc run original.bcm --input-script neko-repro.json
```

命令自动采用包内种子和帧数，校验作品指纹、运行器版本、协议、时间线、最终状态摘要和预算让出次数。不匹配则失败，不能静默忽略。不要再传 `--ticks` / `--frames`、`--seed`、`--event` 或云服务选项。输出 `repro.matched: true` 代表最终调试快照摘要相同；`snapshot` 是本地重放得到的快照。旧 `nekoc-input-v1` 输入脚本保持原有用法，不会被当成录制包。

录制/重放均使用解释器与每帧 2,000,000 指令安全上限，避免 native JIT 与 wasm 的指令计数差异。超限让出次数被记录并校验。每帧确认会计算状态摘要，录制模式的吞吐量可能低于普通游玩；它用于诊断，不用于性能基准。

## 内容与隐私边界

包的 `schema` 为 `nekoc-repro-v1`：

| 字段 | 含义 |
| --- | --- |
| `runner` | NekoC 名称、版本、播放器协议版本 |
| `work_sha256` | 规范化作品 JSON 的 SHA-256（对象键排序、数字按 JS 表示）；用于确认作品，无作品内容 |
| `seed` | 十进制 u64 字符串，避免 JSON 数字丢失大整数精度 |
| `dt` | 固定 `1/60` 秒 |
| `timeline` | 连续帧号、逻辑 `time_ms`、每帧实际送入 VM 的键鼠输入 |
| `diagnostics` | 最终状态 SHA-256、帧数、预算让出次数、输入队列合并/拒绝数、中断标记和固定警告代码 |

时间从帧 1 的 `0 ms` 开始：`time_ms=(frame-1)*1000/60`。保存的是 `StageInput` 处理后的按键、指针目标和状态、绝对拖动位置、滑动方向，以及每帧鼠标位置和按住的键。快速按下/松开保持顺序，录制后不重新做命中检测或猜测 CSS 缩放与手势耗时。这是 **NekoC 接收的输入**，不是完整 DOM 事件日志。

导出采用字段白名单。不包含作品文件、素材、作品名称/URL、账户资料、问答文本、原始变量/列表/日志、扩展结果、麦克风或传感器样本。会包含舞台坐标、按键码及作品内部 actor 标识；键鼠操作本身仍可能透露用户行为，分享前可审阅 JSON。摘要用于对比，不是签名或真实性证明。`complete_recording` 仅表示没有中断或队列拒绝，不是完整 VM 状态证明。

包文件最大 64 MiB，每帧最多 256 个事件、256 个按键，目标标识最多 4096 个 UTF-16 单元；未知字段一律拒绝。只对可信作品运行重放：录制包不是沙箱，固定指令上限也不替代作品安全审查。账户数据不会从宿主接入录制会话，但若作品自身将私人信息编码进 actor 标识或键鼠操作，分享者仍需审阅。

## 不确定依赖与限制

录制模式从输入与执行入口隔离以下依赖，并在包里始终列出警告代码；这不是逐积木的依赖扫描：

- `audio`：不发送真实音频完成通知，不回放声音。等待音频完成的脚本可能保持等待。
- `real_time`：日期/计时来自固定虚拟时钟，UTC 偏移为 0；不录入真实日期或浏览器时区。
- `cloud`：录制会话不接入云后端；CLI 不接受额外云选项。
- `external_inputs`：不采样麦克风/设备，不接收远程扩展、问答、舞台对话等非键鼠宿主输入。有远程扩展的会话拒绝开始录制；录制时被省略的其他输入标记 `omitted_inputs`。
- `asset_geometry`：不把浏览器解码后的造型遮罩、RGB、视频元数据放入包或 VM；素材碰撞/颜色感知等使用共同的无宿主素材信息路径，可能与普通浏览器游玩不同。

因此，这个版本适合从头复现确定性的键鼠逻辑，**不承诺复现普通游玩中依赖音频、外部服务或浏览器素材感知的问题**。录制期间性能选项锁定；输入时间取已提交的帧而非真实墙钟。不同构建/架构若得到不同状态摘要，CLI 会报告失败。最终摘要来自现有 `debug_snapshot`，不是完整 VM 内存序列化，不能证明未暴露的内部状态全部相等。

本功能证明的是 NekoC 录制与 NekoC 重放一致。未增加官方编辑器/播放器一致性的声明；官方键鼠语义参考现有 `docs/input-kn.md` 等证据，录制包本身未在官方播放器验证。未参考或移植 HateNeko 代码。

静态 wasm 与扩展均分发相同前端模块，录制逻辑位于共用 Rust Player SDK；本轮实测覆盖原生 HTTP/WebSocket 后端，wasm 跨架构端到端一致性仍未验证。

## 协议与验证

握手扩展为 `nekoc_extension_handshake:1`，附 `nekoc_repro:{seed:"1"}` 和空 `extensions`。后端 ready 消息含 `repro` 元数据；`{repro_status:true}` 只读返回状态摘要、帧数和预算让出次数。普通播放保持现有协议。录制帧仅接受白名单输入；未知字段、事件、越界帧号、无效时间、超量事件、错版本/指纹都明确报错。

回归覆盖：`tests/r2-repro.test.mjs`（字段白名单、已确认前缀、快速按键/缩放拖动、宿主输入隔离）；`tests/r2_repro.rs`（确定性录制与 CLI 重放、坏包拒绝）；`tests/r2-repro-browser.test.mjs`（真实浏览器按钮、下载包、另进程 CLI 快照对比，KN/K4）。

```sh
# 仓库工作流中 cargo 通过指定入口运行
bash E:/nekoc-wt/_cargo.sh test --test r2_repro
node --test tests/r2-repro.test.mjs
# 先构建 web、nekoc；Linux 可用 Chromium，Windows 默认 Edge
NEKOC_REPRO_E2E=1 NEKOC_NODE_MODULES=/path/to/node_modules node --test tests/r2-repro-browser.test.mjs
```
